# مواصفة «باب استقبال الطلب» — Order Intake API

هذا المستند يشرح النقطة (endpoint) اللي لازم سيرفرك (الباك-إند) يوفّرها عشان
الموقع يحفظ كل طلب في قاعدة بياناتك (المصدر الأساسي). **اختياري لكن موصى به بشدة**:
هو طبقة الأمان اللي تضمن إن الطلب ما يضيع حتى لو فشل تلقرام.

الموقع يرسل الطلب لهالنقطة من **جهة الخادم** (من داخل `/api/order`)، فالتوكن
والاتصال ما ينكشفان للمتصفح.

---

## التفعيل (من غير أي تعديل بالكود)

في ملف البيئة `.env` بالموقع، اضبط:

```
ORDER_INTAKE_URL=https://api.YOUR-DOMAIN.com/api/v2/orders
ORDER_INTAKE_TOKEN=اختياري-سر-مشترك-للتحقق
```

- لو `ORDER_INTAKE_URL` غير مضبوط → الموقع يتجاهل هالطبقة (يرسل تلقرام فقط).
- لو `ORDER_INTAKE_TOKEN` مضبوط → الموقع يرسل ترويسة `Authorization: Bearer <token>`،
  ويُفترض سيرفرك يتحقق منها. لو تركته فارغًا → النقطة عامة بدون تحقق.

---

## الطلب (Request)

```
POST  {ORDER_INTAKE_URL}
Content-Type: application/json
Authorization: Bearer {ORDER_INTAKE_TOKEN}   ← فقط إذا ضبطت التوكن
```

### شكل الجسم (Body)

```jsonc
{
  "orderNumber": "AQ-260925-4821",     // رقم الطلب المتولّد بالموقع (فريد)
  "contractType": "سكني",              // "سكني" أو "تجاري"
  "whatsappNumber": "0512345678",      // رقم واتساب العميل للتواصل
  "createdAt": "2026-09-25T12:00:00.000Z",
  "source": "web",
  "sections": [                          // تفاصيل العقد، مقسّمة أقسام
    {
      "title": "ملخص الطلب",
      "fields": [
        { "label": "نوع العقد", "value": "سكني" },
        { "label": "تاريخ البداية", "value": "2026-10-01" },
        { "label": "المدة", "value": "سنة" }
      ]
    },
    {
      "title": "بيانات المالك",
      "fields": [
        { "label": "رقم الهوية", "value": "1xxxxxxxxx" },
        { "label": "الجوال", "value": "05xxxxxxxx" }
      ]
    }
    // ... بقية الأقسام (المستأجر، الوحدة، الإيجار ...)
  ],
  "notes": "ملاحظات إضافية (اختياري)"
}
```

> الحقول داخل `sections` نصّية جاهزة للعرض (label/value)، فتقدر تخزّنها كما هي
> (JSON) في عمود واحد، أو تفكّكها حسب حاجتك. الصور والمرفقات **لا تُرسل** هنا في
> هذه المرحلة (تُجمع لاحقًا عبر واتساب) — نقدر نضيف رفع الملفات لاحقًا لو تبي.

---

## الرد (Response)

- **نجاح:** أي كود `2xx` مع جسم JSON:

```json
{ "ok": true, "id": 123 }
```

- **فشل:** أي كود غير `2xx`. الموقع بيعتبر الحفظ فشل، **لكنه بيكمل** ويوصل الطلب
  عبر تلقرام/الإيميل، ويعرض للعميل شاشة نجاح إذا نجحت أي قناة.

---

## نقاط مهمة للباك-إند

1. **عام بدون تسجيل دخول** — لا يتطلب جلسة مستخدم (الطلب من زائر غير مسجّل).
2. **تحقّق بسيط** — لو استخدمت `ORDER_INTAKE_TOKEN`، تأكد منه قبل القبول. يُفضّل
   أيضًا حد أدنى من الحماية ضد التكرار/الإساءة (rate limiting).
3. **منع التكرار (Idempotency)** — `orderNumber` فريد لكل طلب؛ لو وصلك نفس الرقم
   مرتين (إعادة محاولة)، لا تُنشئ سجلًّا مكرّرًا.
4. **التخزين هو الأهم** — بمجرد ما تخزّن الطلب في قاعدة البيانات وترجع `2xx`،
   صار الطلب محفوظًا عندك كمصدر أساسي ولو ما وصل تلقرام.
5. **اختياري:** تقدر من هالنقطة نفسها ترسل إشعارك الخاص (تلقرام/إيميل/واتساب) من
   السيرفر لموثوقية أعلى — ولو سويت كذا، نقدر نوقف إرسال تلقرام من الموقع ونخليه
   كله من عندك.

---

## لوحة الطلبات (اقتراح)

بعد ما تخزّن الطلبات، أنشئ صفحة بسيطة في لوحة تحكّمك تعرض الطلبات (رقم الطلب،
التاريخ، نوع العقد، رقم واتساب، الحالة) — تكون هي المرجع لو احتجت ترجع لأي طلب.
