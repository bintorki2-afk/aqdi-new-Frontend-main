# قائمة الإطلاق — عقد إيجار (صقر 1)

هذا الملف يلخّص ما تبقّى **منك أنت** لإطلاق الموقع بمساره الجديد (بدون تسجيل
دخول، بدون بوابة دفع، الطلبات تصل عبر واتساب/تلجرام). كل الشغل البرمجي جاهز
على فرع `rearchitecture`، وفرع `master` المباشر (اللايف) لم يُمسّ.

---

## الوضع الحالي

- **اللايف (`origin/master`)** = `315bd2b` — إزالة تطبيق الجوال فقط (المرحلة 1).
- **كل التطوير الجديد على `origin/rearchitecture`**:
  - `c346be3` مسار الطلب: بدون تسجيل دخول/دفع/OTP + إرسال إلى تلجرام
  - `0c58bfe` طبقة موثوقية الطلب + مواصفة استقبال الطلب للسيرفر
  - `909d9bd` إصلاح تمرير {year} لحقوق النشر
  - `3512c0f` بنية تتبّع الإعلانات: GTM + Consent Mode + حدث تحويل الطلب
  - `175b4cb` المدونة الحقيقية بملفات محتوى + مقال مبني على الأرقام
  - `1e085b4` توثيق نظام المدونة + تفعيل النشر التلقائي
  - `97b396f` SEO: خريطة موقع + robots + وسوم المقالات

## خبر مهم تم التحقق منه

مسار إنشاء العقد للزائر **غير المسجّل** يعتمد فقط على نقاط نهاية **عامة**
(القوائم المنسدلة: المناطق، المدن، مدد العقد، أنواع الدفع، أنواع/استخدامات
الوحدة، صفة المستأجر، الأعمال الورقية). هذه المسارات في السيرفر (Laravel)
مسجّلة بوسيط `api` فقط بدون `auth:sanctum`، فهي متاحة بلا تسجيل دخول أصلًا.
خطوات المعالج لم تعد تتصل بالسيرفر، وصفحة المراجعة تقرأ من المخزن المحلّي +
القوائم العامة فقط. **النتيجة: القوائم المنسدلة تعمل بدون تسجيل دخول — لا حاجة
لأي تعديل على السيرفر لإطلاق مسار الطلب.**

## المطلوب منك (بالترتيب)

### 1) متغيّرات البيئة على استضافة الموقع (Vercel مثلًا)

مطلوبة ليصلك الطلب:

- `TELEGRAM_BOT_TOKEN` — توكن البوت من @BotFather (سرّي، بدون `NEXT_PUBLIC_`).
- `TELEGRAM_CHAT_ID` — معرّف المحادثة/القناة التي تستقبل الطلبات.
  (طريقة الحصول عليه موضّحة داخل `.env.example`.)
- `NEXT_PUBLIC_BASE_URL` — رابط السيرفر المباشر مع `/api/v2` بدون شرطة أخيرة.

مطلوبة للإعلانات والتتبّع (كل الدانه عندك):

- `NEXT_PUBLIC_GTM_ID` — معرّف حاوية Google Tag Manager. عند ضبطه يُحمّل GTM
  ووضع الموافقة (Consent Mode) وإشعار الكوكيز، وكل طلب يُرسل حدث
  `generate_lead` تستخدمه كتحويل في Google Ads / GA4 / Meta / TikTok / X /
  Snap — كلها تُربط من داخل واجهة GTM بلا تعديل كود. (التفاصيل في
  `docs/analytics-and-ads.md`.)
- `NEXT_PUBLIC_SITE_URL` — دومين الموقع النهائي (لِـ sitemap/robots والروابط).
- `NEXT_PUBLIC_LEAD_VALUE` — اختياري: قيمة الطلب بالريال على حدث التحويل.

اختيارية (طبقات موثوقية إضافية لِـ `/api/order`):

- `RESEND_API_KEY` + `ORDER_EMAIL_TO` + `ORDER_EMAIL_FROM` — نسخة احتياطية
  بالإيميل لكل طلب (الثلاثة مطلوبة معًا للتفعيل).
- `ORDER_INTAKE_URL` (+ `ORDER_INTAKE_TOKEN` اختياري) — تخزين الطلب في قاعدة
  بياناتك كمصدر حقيقة. (المواصفة في `docs/order-intake-api.md`؛ اقرأ القسم
  «تحسينات اختيارية» أدناه أولًا.)

> ملاحظة: أي متغيّر `NEXT_PUBLIC_*` يُدمج في حزمة المتصفح وقت البناء، فلا بد من
> إعادة بناء/نشر بعد تغييره. متغيّرات تلجرام والإيميل خادمية فقط ولا تُرسل للمتصفح.

### 2) الدمج والنشر

بعد مراجعتك ورضاك عن الفرع:

```
git checkout master
git merge --no-ff rearchitecture
git push origin master
```

ثم أعِد نشر الموقع. (لم أدفع أي شيء إلى `master` المباشر — قرار الدمج قرارك.)

### 3) تشغيل المدونة الذكية تلقائيًا

المهمة المجدولة «نشر مقال المدونة الأسبوعي» جاهزة لكنها غير مربوطة بعد. لتعمل
بالكامل بدونك تحتاج أحد أمرين:
- ربط المهمة بهذا الكمبيوتر من تطبيق Claude لسطح المكتب، أو
- تزويدي بتوكن GitHub حتى تدفع المقالات الجديدة إلى المستودع من السحابة.
(تفاصيل نظام المدونة في `docs/blog-system.md`.)

### 4) الإعلانات

أنشئ حاوية GTM ومعرّفات البكسل (Google Ads / Meta / TikTok / X / Snap) وضعها
داخل GTM، ثم اربط حدث `generate_lead` كتحويل. البنية جاهزة بالكامل من طرف الكود.

## اختبار سريع بعد النشر

1. افتح صفحة إنشاء العقد بدون تسجيل دخول — يجب أن تظهر القوائم المنسدلة وتتنقّل
   بين الخطوات.
2. أكمل حتى خطوة الإرسال، أدخِل رقم واتساب صحيح، واضغط إرسال.
3. تحقّق من وصول الطلب إلى تلجرام (وإن فعّلت الإيميل/التخزين، تحقّق منهما).
4. تحقّق من `/{الدومين}/sitemap.xml` و`/{الدومين}/robots.txt` وأن `/blog` يعمل.

## تحسينات اختيارية (أقدر أنفّذها عند طلبك)

- **إرسال صور الصك مع الطلب تلقائيًا**: حاليًا الطلب نصّي وتُكمَّل الصور عبر
  واتساب. يمكن إضافة رفع الصور وتمريرها لتلجرام، لكنها تزيد التعقيد.
- **نقطة استقبال الطلب في السيرفر (تخزين بقاعدة البيانات)**: السيرفر مُحصَّن
  أمنيًا عمدًا و`POST /leads` الحالي محمي بتوكن العميل. إضافة نقطة عامة للكتابة
  تفتح سطح هجوم (سبام)، لذا أفضّل أن أبنيها بعد موافقتك على النموذج الأمني
  (تحديد rate-limit وتحقّق صارم وربما مفتاح سرّي مشترك).
- **تنظيف كود الدفع/OTP الميت** المتبقّي من المسار القديم.
